## Safe deployment order

1. In Cloud Shell, pull main in ~/printprofit-pro-test and inspect git status before deployment. The local functions/.env.printprofit-test and firebase.test-rules.json belong to the sandbox. Copy functions/.env.printprofit-fd30f.example to functions/.env.printprofit-fd30f. This local production file starts with PRINTPROFIT_BILLING_ENABLED=false and contains the verified live price IDs. Set PRINTPROFIT_OWNER_EMAIL to the verified Firebase Auth email for the owner account in this local file only. Never commit project-specific .env files.
2. Create a restricted live-mode Stripe API key with the calls required by functions/index.js (prices retrieve; customers create/retrieve; subscriptions list/cancel; Checkout sessions create; billing portal sessions create). Store it as the Firebase Secret Manager secret STRIPE_SECRET_KEY in printprofit-fd30f through a masked input. Never paste keys into GitHub, the website, screenshots or chat. The function rejects test-mode keys in production. Confirm the stored key has the expected rk_live_ or sk_live_ prefix without displaying its value.
3. In the live Stripe Dashboard, open the **disabled** webhook destination we_1USt0FV05QYif292WESjWOm9 and privately reveal its signing secret. It targets https://europe-west2-printprofit-fd30f.cloudfunctions.net/stripeBillingWebhook and is subscribed to the ten events used by the function. Store this destination's whsec_ secret as STRIPE_WEBHOOK_SECRET in the production Firebase project, through masked input. Do not use the earlier disabled destination we_1USszYV05QYif292W6R5JNqe or its exposed signing secret. Keep public checkout off during setup.
4. Run npm ci --prefix functions and npm test --prefix functions. Deploy with npx -y firebase-tools@latest deploy --config firebase.billing.json --project printprofit-fd30f --only functions:printprofit-billing. Confirm all six functions deployed in europe-west2, including the Auth deletion reconciliation trigger. A failed or partial deployment does not satisfy this check.
5. Once all six functions are running, enable only the current live webhook destination we_1USt0FV05QYif292WESjWOm9 in Stripe. Leave the earlier destination disabled and remove it. Review and deploy firestore.rules to production using an explicit Firestore rules configuration. The billing collections must remain server-only. Check existing account sync, live Firebase Auth authorized domains and owner email verification.
6. Check the webhook endpoint rejects unsigned requests and getProAccess rejects signed-out callers. Check a verified non-subscriber and the verified owner account; the owner should show Pro without a trial or payment. Do not mistake a Stripe sandbox test event for a valid live event: wrong-mode events are deliberately rejected.
7. For a controlled live canary only, change the local production .env flag to PRINTPROFIT_BILLING_ENABLED=true and redeploy the billing functions. Keep the public website's config/billing-config.js flag false. Use a temporary, production-wired frontend preview with its browser billing flag true and only invite the tester. With a separate non-owner account, start a live seven day trial with a real payment method after the user's review. Confirm the return page, entitlement on another device, portal and cancellation. Inspect the resulting live Stripe webhook deliveries for 2xx; check monthly and annual price selection, renewal amounts, first charge date and terms. A sandbox test does not count as a live payment test. If canary checks fail, turn the backend flag off again while fixing the issue.
8. After the canary and operational checks pass, enable config/billing-config.js on the public website and verify the public account flow. To stop new checkouts, set the public browser and backend flags false without deleting accounts or subscriptions; existing customers must retain portal management.

## Operational checks

Confirm tax treatment and customer jurisdictions before charging; an inclusive price does not itself calculate or collect tax. Check Stripe trial-ending notifications and renewal/cancellation emails, privacy and purchase terms, live Firestore rules, account deletion behavior, billing alerts and the downgrade view of saved work. Monitor Stripe webhook failures and Firebase errors during the first subscriptions.

The live API key and live webhook signing secret must be entered in the user's Stripe/Firebase session. An agent connection to Cloud Shell has not been available. No live credential value belongs in chat.
